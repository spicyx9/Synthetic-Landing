## Polices

Famille : Inter uniquement (styles.css:3119, 3134, 3776, 4087, 4200, 4234, 4270 ; demo.css:18 utilise la pile système pour un composant). Demande : `https://fonts.googleapis.com/css2?family=Inter:wght@400;500;600;700;800&display=swap` sur les 26 pages, en `<link rel="stylesheet">` bloquant, avec `<link rel="preconnect">` vers fonts.googleapis.com et fonts.gstatic.com (`crossorigin`) sur toutes les pages, `display=swap` partout, aucun `preload`, aucune police auto-hébergée, aucun `@font-face` local. Chargement réel (curl, UA Chrome Android, via le proxy) : la feuille fait 12 535 o et déclare 35 `@font-face` (7 sous-ensembles x 5 graisses, `font-display: swap`) ; pour chaque sous-ensemble les 5 graisses pointent vers le même fichier woff2 variable : `latin` = 85 272 o (identique pour `latin-ext`). Une page FR ou EN ne déclenche que `latin` (les caractères accentués, œ et les guillemets sont dans la plage `latin`), soit environ 98 Ko en première visite, puis cache navigateur (Google Fonts sert les woff2 avec un cache d'un an). Dans Chromium de ce conteneur la requête échoue (`ERR_CERT_AUTHORITY_INVALID`), donc 0 o mesuré par page et le texte est rendu en police de repli ; Lighthouse compte cette feuille comme bloquante (780 ms estimés) et son échec comme une erreur console (score Bonnes pratiques 96 au lieu de 100 attendu en production). Graisses demandées : 400, 500, 600, 700, 800. Graisses présentes dans les CSS : 400 (22 déclarations), 500 (41), 600 (59), 700 (57), 800 (22), plus 550 (4 fois : home.css:252) et 650 (5 fois : home.css:255, solution-page.css:500, 504, 532) qui ne sont pas demandées et sont donc rendues avec les instances 600 et 700. Correction : demander la plage variable `wght@400..800` (même fichier, mêmes octets) et charger la feuille en preload asynchrone (voir constat MAJEUR 5).
